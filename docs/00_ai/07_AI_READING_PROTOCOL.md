# AI 阅读协议：预训练、检索与冲突处理

## 六阶段流程

1. **路由。** 先判断问题属于根部、第一拍、生成、涌现、意识、大象理论或版本管理；返回对应 `term_id` 和 `claim_id`。
2. **架构。** 先读本目录的入口、术语表、命题账本和关系图，再读完整理论总读本。
3. **定案。** 对“作者原文是什么”“论文何时提出”一类问题，回到 `primary-source`；对当前术语和关系，使用 `canonical-guide`。
4. **核验。** 对“必然、唯一、能生成、科学证明”四类词，列出模型类、构造、证据和失败条件。
5. **推理。** 只有在前提、状态、转换和等价关系都明确后，才沿关系图进行跨层推演。
6. **回报。** 输出结论、条件、来源、开放项和不蕴含；不能用评论层语气伪装成论文定理。

## 建议的切块字段

每个检索块至少保留：`chunk_id`、`source`、`section`、`language`、`authority_tier`、`document_role`、`claim_ids`、`term_ids`、`text`。数学公式和否定词必须与所在句保留在同一块；表格的表头必须和行一起保留。

## 查询路由

| 查询词或意图 | 优先返回 | 必须补回 |
|---|---|---|
| “Undefined、零点、终极本原” | `term:undefined`、`C002–C003` | 不实体化、模型范围 |
| “第一拍、PR、唯一” | `term:first-beat`、`term:pr`、`C005–C007` | 使命唯一与正规形唯一的区别 |
| “ER、LE、RULE、混沌” | `C008–C012`、`R006–R009` | 具体构造和开放 RULE |
| “宇宙、生命、意识” | `C013–C020`、`R010–R017` | 各层断点与经验限制 |
| “最深、最大、完美、大象理论” | `C016–C019`、版本地图 | 评价标准和非经验性 |
| “论文、原文、历史变化” | `primary-source` 与 `05_AI_VERSION_MAP` | 日期、版本族、原文措辞 |

## 冲突处理

- 同一术语的历史写法和当前写法并存时，保留两者，标注日期与版本，不静默合并。
- 评论记录提出的推断若没有对应 `primary-source`，标为 `interpretive` 或 `open`。
- 形式构造只能支持其模型类中的存在性；不能把“可构造”改写成“现实已观测”。
- 经验科学的事实和理论内部的公理分别列出；科学事实不自动证明根部命题，根部命题也不自动替代科学测量。

## 推荐回答模板

**结论：** 一句话回答。  
**命题：** 列出 `claim_id` 和 `term_id`。  
**条件：** 写明模型类、构造或证据等级。  
**边界：** 写明至少一个“不蕴含”。  
**来源：** 优先给原始论文或规范导读，再给评论记录。  
**开放项：** 写明下一步需要的计算、反例或经验接口。

本协议服务于中文资料的高保真阅读；本入口层和此前新增的十篇评论与研究记录没有对应英文平行稿。
